# 홀 좌석 현장 운영 시스템 구조

## 현재 단계

- Next.js App Router와 TypeScript 기반의 정식 애플리케이션 뼈대
- 검증된 태블릿 운영 미리보기와 목업 데이터
- Supabase 브라우저·서버 클라이언트 및 공개 카탈로그 조회 연결
- 홀·층·좌석·행사·회차·담당 권한·회차 좌석·감사 이력 스키마 적용
- 공개 스키마 RLS와 최소 권한 정책 적용
- 실제 로그인, 배부·입장 트랜잭션 함수, Realtime 연결은 다음 단계에서 적용

## 좌석 데이터 상태

- 하은홀 2층은 도면 기준 188석이 모두 등록되어 있습니다.
- 하은홀 1층은 도면 기준 506석이 모두 등록되어 있습니다.
- J·K열 좌측 블록은 각각 3~6번으로 확정되어 화면과 DB에 반영되어 있습니다.
- 아트홀과 예랑홀은 정원과 층 정보만 등록했으며 실제 도면을 받기 전 좌석 형상을 생성하지 않습니다.

## 운영 범위

모든 화면은 `홀 → 행사 → 회차` 선택을 기준으로 동작합니다. 서로 다른 홀의 운영 수치는 합산하지 않습니다.

## 보안 기준

- 브라우저에는 프로젝트 URL과 Publishable key만 사용합니다.
- DB 비밀번호, Secret key, Service Role key는 저장소에 커밋하지 않습니다.
- 공개 스키마의 테이블에는 RLS와 업무 범위별 정책을 적용합니다.
- 좌석 배부·입장·취소·재배정은 클라이언트 상태가 아니라 DB 트랜잭션으로 확정합니다.
